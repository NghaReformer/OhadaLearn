### 1.1 Hardcoded Hex Colors — Theme Token Bypass

#### `src/lib/playgrounds/bank-reconciliation/components/CategoryBreakdownDonut.svelte:30–40`
**Severity: HIGH**

`CATEGORY_COLORS` is a hardcoded `Record<ItemCategory, string>` mapping nine categories to raw hex values (`#6ea8fe`, `#22c55e`, `#f59e0b`, etc.). These bypass the design-token system entirely. If the theme changes or a second theme is added, this donut chart will remain visually inconsistent.

**Suggested fix:** Expose these as CSS custom properties in `src/lib/theme/tokens.ts` (e.g., `reconCatCheck`, `reconCatTransit`, …) or map categories to existing semantic tokens (`--green`, `--amber`, `--error`, `--accent`) where possible, and read them from `getComputedStyle` in the component.

**Suggested fix:** Read CSS custom properties via `getComputedStyle(document.documentElement).getPropertyValue('--green')` etc. at component mount, or add dedicated match-type CSS custom properties to the theme.

### 2.1 VAT / TVA Computation Playground

**Title (EN):** VAT Accounting Simulator  
**Title (FR):** Simulateur de comptabilité TVA

**Target learner:** Licence 2, practicing professional

**Pedagogical objective:** Students routinely confuse collected VAT (liability) with deductible VAT (asset), and miscalculate the TVA à décaisser / TVA à récupérer balance. SYSCOHADA Acte Uniforme requires specific account classes (4441, 4451, 4455) that differ from French Plan Comptable.

**Core interaction:** User enters a series of purchases and sales with mixed VAT rates (0%, 8%, 18% — OHADA member state typical rates). The playground builds the VAT ledger live, shows the netting computation, and generates the journal entries for the monthly VAT return settlement.

**Minimum viable inputs/outputs:**
- Input: line items (description, HT amount, VAT rate, buy/sell flag)
- Output: collected VAT total, deductible VAT total, net payable/refundable, SYSCOHADA journal entries (debit 4441/4451, credit 4455)

**Why it complements existing playgrounds:** Journal Entry teaches the mechanics of double-entry; this playground applies it to a specific statutory obligation that every OHADA-zone enterprise faces monthly. No current playground covers VAT/TVA.

### 2.2 Fixed Asset Lifecycle Playground

**Title (EN):** Fixed Asset Lifecycle Tracker  
**Title (FR):** Suivi du cycle de vie des immobilisations

**Target learner:** Licence 3, Master

**Pedagogical objective:** Learners conflate acquisition cost, carrying value, depreciation, revaluation surplus, and disposal gain/loss. SYSCOHADA (OHADA Uniform Act) prescribes specific treatment for asset revaluation (comptes 1051, class 2) and requires disposal journal entries that students consistently get wrong.

**Core interaction:** Timeline scrubber across an asset's life: acquire → depreciate (straight-line or declining-balance) → optionally revalue → dispose (full or partial sale). Each timeline event auto-generates the SYSCOHADA journal entry. A carrying-value chart updates in real time.

**Minimum viable inputs/outputs:**
- Input: acquisition cost, date, useful life, depreciation method, optional revaluation amount and date, disposal price and date
- Output: year-by-year depreciation schedule, carrying value chart, journal entries per event, gain/loss on disposal

**Why it complements existing playgrounds:** The static depreciation HTML playground shows schedule calculation only. This extends it into the full lifecycle with journal entries, bridging into the Journal Entry playground's domain.

### 2.3 Financial Statement Analysis Playground

**Title (EN):** SYSCOHADA Ratio Analyser  
**Title (FR):** Analyseur de ratios SYSCOHADA

**Target learner:** Licence 3, Master, practicing professional

**Pedagogical objective:** Financial ratio interpretation in an OHADA context uses SYSCOHADA balance sheet structure (class-1 to class-5 decomposition) which differs from IFRS or French PCG. Learners need to build intuition for how changes in one line item ripple through solvency, liquidity, and profitability ratios.

**Core interaction:** Simplified SYSCOHADA balance sheet and income statement with editable cells. As the learner changes a value (e.g. increases long-term debt), ratios update live: fonds de roulement, besoin en fonds de roulement, trésorerie nette, ratio d'endettement, rentabilité économique. A traffic-light panel flags ratios outside sector-typical ranges.

**Minimum viable inputs/outputs:**
- Input: 15–20 key balance sheet / P&L line items (grouped by SYSCOHADA class)
- Output: 8–10 computed ratios with formulas exposed, trend arrows, traffic-light status

**Why it complements existing playgrounds:** CVP covers internal cost analysis; this covers external financial statement reading — a distinct and heavily examined skill in OHADA-zone professional exams (DESCOGEF, expertise comptable).

### 2.4 Payroll & Social Charges Calculator

**Title (EN):** OHADA Payroll Simulator  
**Title (FR):** Simulateur de paie OHADA

**Target learner:** Licence 2/3, HR professionals

**Pedagogical objective:** Payroll accounting under OHADA member states requires computing gross pay, employer/employee social contribution rates (CNPS/CNSS vary by country), income tax (IRPP with bracket schedules), and net-to-pay — then generating the journal entries debiting payroll expense accounts and crediting social liability accounts. Students frequently mix up which charges are employer-borne vs. employee-borne.

**Core interaction:** User selects an OHADA member state (Cameroon, Côte d'Ivoire, Sénégal, Congo-B — four most common), enters gross salary, allowances, and headcount. The playground shows the decomposition (base, cotisations CNPS, IRPP brackets, net imposable, net à payer) and the full payroll journal entry using SYSCOHADA class-4 accounts.

**Minimum viable inputs/outputs:**
- Input: country selector, gross salary, transport/meal allowance, number of employees
- Output: pay slip breakdown, employer total cost, journal entry (class 6 expense + class 4 liabilities)

**Why it complements existing playgrounds:** No current playground covers labor costs. This is a high-frequency topic in OHADA professional exams and a gap in the demo catalog.

### 2.5 Foreign Currency Transaction Playground

**Title (EN):** Foreign Currency Revaluation  
**Title (FR):** Réévaluation des opérations en devises

**Target learner:** Master, practicing professional (international trade context)

**Pedagogical objective:** SYSCOHADA requires translation of foreign-currency transactions at transaction-date rates and revaluation at closing rates, with exchange gains/losses posted to specific accounts (compte 776 / 676). This two-step process (initial recognition vs. year-end revaluation) is systematically confused with IFRS IAS 21 treatment.

**Core interaction:** User enters a foreign-currency transaction (e.g. USD invoice for goods), sets the transaction-date rate and a year-end closing rate. The playground shows: initial recording in FCFA at transaction rate, revaluation entry at year-end, disclosure of the unrealized gain/loss — all in SYSCOHADA journal entry format. A rate sensitivity slider lets the user explore how exchange rate movements affect reported profit.

**Minimum viable inputs/outputs:**
- Input: transaction amount (USD/EUR/GBP), transaction date rate, closing rate, transaction type (payable/receivable)
- Output: initial entry, revaluation entry, net position, gain/loss in FCFA

**Why it complements existing playgrounds:** Interest and TVM cover domestic time-value mechanics. This addresses cross-currency mechanics that are increasingly relevant as OHADA-zone firms trade internationally — and completely absent from the current catalog.
