## 1. Bugs & Issues

### B1 — Missing CSS variables `--orange`, `--blue`, `--red` in theme generator
**Severity: HIGH**
**Files:**
- `src/lib/theme/css-generator.ts` (entire file — vars never emitted)
- `src/lib/components/playground/KpiStrip.svelte:76`
- `src/lib/playgrounds/amortization/components/ChartPanel.svelte:436,444,448,493,501,505,515,529,533`
- `src/lib/playgrounds/amortization/components/ScheduleTable.svelte:240,246,259,265`
- `src/lib/playgrounds/amortization/components/InputsPanel.svelte:604–605`
- `src/lib/playgrounds/bank-reconciliation/components/LedgerPanel.svelte:149,175,208–222`
- `src/lib/playgrounds/bank-reconciliation/components/VarianceScale.svelte:252,260,264,410,413,416`
- `src/lib/playgrounds/bank-reconciliation/components/TransactionJournal.svelte:271,276,378,382`
- `src/lib/playgrounds/bank-reconciliation/components/BankStatementPanel.svelte:175`

`css-generator.ts` emits `--green`, `--amber`, `--error` but never `--orange`, `--blue`, or `--red`. Every `var(--orange, #f59e0b)`, `var(--blue, #3b82f6)`, and `var(--red, #ef4444)` throughout the codebase falls through to its hardcoded fallback — the CSS variable fallback is always in effect, making these hex values the real production colors. This defeats the theme token system and blocks future retheme.

**Fix:** Add `orange`, `blue`, and `red` fields to `ThemeTokens.colors` in `tokens.ts`, set values in `defaultTheme`, and emit `--orange`, `--blue`, `--red` in `css-generator.ts`.

### B2 — Hardcoded hex palette in `CategoryBreakdownDonut.svelte`
**Severity: HIGH**
**File:** `src/lib/playgrounds/bank-reconciliation/components/CategoryBreakdownDonut.svelte:30–40`

`CATEGORY_COLORS` is a plain TypeScript constant with 9 hardcoded hex values (`#6ea8fe`, `#22c55e`, `#f59e0b`, `#10b981`, `#ef4444`, `#a855f7`, `#06b6d4`, `#ec4899`, `#fb923c`). These are passed as SVG `stroke` props and as `style="background: {seg.color}"` inline styles for legend swatches (line 120). They bypass the theme system entirely and cannot be rethemed.

**Fix:** Map each `ItemCategory` to a CSS variable reference (e.g., `var(--accent)`, `var(--green)`, `var(--amber)`). For categories with no existing token equivalent, define new semantic tokens in `tokens.ts` (e.g., `--purple`, `--cyan`, `--pink`). Pass colors as CSS strings through the theme system so they respond to future theme switches.

### B3 — Privacy page entirely in hardcoded English, `$t` imported but unused
**Severity: HIGH**
**File:** `src/routes/[lang]/privacy/+page.svelte:1–26`

The page imports `{ t }` from `$lib/i18n` but never calls it. All headings (`"Privacy Policy"`, `"What we collect"`, `"Analytics"`, `"No cookies"`, `"Your rights"`, `"Contact"`) and all body paragraphs are raw English strings. French users at `/fr/privacy` see the English-only page. This is an i18n parity violation — CLAUDE.md requires all user-facing strings to be bilingual.

**Fix:** Create `privacy.en.ts` and `privacy.fr.ts` namespaces in `src/lib/i18n/namespaces/`. Add translation keys for each heading and paragraph. Replace raw strings with `$t('privacy.heading')`, etc. Run `npm run i18n:check` to verify parity.

### P1 — Inventory Valuation Methods
**EN:** Inventory Valuation Methods | **FR:** Méthodes d'évaluation des stocks

**Target learner:** Licence 2 / Licence 3

**Pedagogical objective:** Students routinely confuse FIFO (PEPS), LIFO (DEPS — note: not permitted under SYSCOHADA), and Weighted Average Cost (CMUP), and struggle to understand how the choice of method affects cost of goods sold and ending inventory, especially under price fluctuations.

**Core interaction:** The learner inputs a sequence of purchases (date, qty, unit cost) and sales (date, qty). The playground recomputes the inventory ledger in real time under the selected method (FIFO or CMUP — SYSCOHADA-permitted only), displaying a running stock card alongside COGS and closing inventory value.

**Minimum viable inputs / outputs:**
- Inputs: initial stock, 4–8 purchase/sale events with quantities and prices
- Outputs: itemised stock card table, total COGS, closing stock value, gross profit line
- Toggle: FIFO vs CMUP with animated transition showing how numbers change

**Why it complements existing playgrounds:** The journal-entry playground records transactions but does not model inventory flow. This playground sits upstream — students understand what numbers feed the inventory account before they journal them.

---

### P2 — VAT / TVA Calculator
**EN:** VAT Input/Output Reconciliation | **FR:** Déclaration de TVA (Taxe sur la Valeur Ajoutée)

**Target learner:** Licence 2 / practicing professional

**Pedagogical objective:** Students in the OHADA zone struggle with the mechanics of recoverable VAT — specifically, the difference between VAT collected on sales (TVA collectée), VAT paid on purchases (TVA déductible), and VAT actually remitted to the tax authority. The netting logic and the handling of mixed-use (partial exemption) purchases cause persistent errors.

**Core interaction:** Learner enters a set of purchase invoices (excl. tax, VAT rate, deductibility %) and sales invoices (excl. tax, VAT rate). The playground computes TVA collectée, TVA déductible, TVA due (or crédit), and shows a SYSCOHADA-style declaration summary alongside the journal entries required (accounts 4456, 4457, 4455).

**Minimum viable inputs / outputs:**
- Inputs: 3–6 purchase lines (HT, rate, deductible?), 3–6 sale lines (HT, rate)
- Outputs: TVA collected, TVA deductible, net TVA payable, journal entries preview
- Rates: 18% standard (CEMAC), 0% exempt, configurable for different OHADA member states

**Why it complements existing playgrounds:** No existing playground touches indirect taxation. VAT literacy is mandatory for any practicing accountant in the OHADA zone and is tested on professional exams (DSCG/DPECF equivalents).

---

### P3 — Financial Ratio Analyser
**EN:** Financial Ratio Analysis | **FR:** Analyse financière par ratios

**Target learner:** Licence 3 / Master 1

**Pedagogical objective:** Students can compute individual ratios mechanically but do not understand how ratios interact or how to read a company's financial health holistically. SYSCOHADA balance sheet presentation (Emplois / Ressources) differs from IFRS, creating confusion when switching between frameworks.

**Core interaction:** Learner inputs balance sheet and income statement figures from a simplified SYSCOHADA-format trial balance. The playground computes a dashboard of ratios (liquidity: FR/BFR/TN; solvency: gearing, debt-to-equity; profitability: ROE, ROA, EBITDA margin; activity: DSO, DPO) and renders a radar chart. A "stress-test" slider lets the learner decrease revenue or increase debt to see which ratios breach critical thresholds.

**Minimum viable inputs / outputs:**
- Inputs: 10–15 balance sheet line items + 5 P&L lines (SYSCOHADA format)
- Outputs: ratio table, radar chart, colour-coded health indicator per ratio, plain-language interpretation
- Framework toggle: SYSCOHADA vs IFRS classification to show how reclassification shifts ratios

**Why it complements existing playgrounds:** TVM and amortization focus on individual transactions; this playground operates at the strategic level — connecting transaction data to firm-level analysis that students encounter in corporate finance and auditing courses.

### P4 — Payroll / Fiche de Paie Calculator
**EN:** Payroll Computation | **FR:** Calcul de la fiche de paie

**Target learner:** Licence 3 / practicing professional

**Pedagogical objective:** OHADA-zone payroll involves layered social charges (CNPS cotisations, IRPP tranches, employer contributions) that vary by country and salary bracket. Students confuse gross vs net, employer cost vs employee cost, and which charges hit which accounts (641, 645, 431, 447).

**Core interaction:** Learner inputs gross salary, contract type, and country (Cameroon / Côte d'Ivoire / Senegal selector for CNPS rates). The playground computes employee deductions (CNPS, IRPP), employer contributions, net salary, and employer total cost, then generates the payslip layout alongside the required SYSCOHADA journal entries.

**Minimum viable inputs / outputs:**
- Inputs: gross monthly salary, country, employee category (cadre / non-cadre)
- Outputs: payslip breakdown, employer cost summary, journal entries (641 Salaires bruts, 645 Charges sociales, 431 Sécurité sociale, 447 IRPP)
- Scenarios: comparing salary packages across two OHADA countries

**Why it complements existing playgrounds:** The journal-entry playground uses generic transactions; payroll is a high-frequency, multi-account transaction with country-specific rules that no existing playground addresses.

---

### P5 — Depreciation Comparison: Straight-Line vs Declining-Balance vs Units of Production
**EN:** Depreciation Method Comparison | **FR:** Comparaison des modes d'amortissement

**Target learner:** Licence 1 / Licence 2

**Pedagogical objective:** The existing amortization playground focuses on loan amortization schedules (i.e., debt repayment). SYSCOHADA asset depreciation (Articles 35–38 AUSCGIE) is a distinct concept using different methods and triggers different journal accounts (2818 Amortissements, 6811 Dotations). Students conflate the two.

**Core interaction:** Learner inputs an asset (cost, residual value, useful life, units produced per year). Three depreciation schedules run side-by-side with an animated bar chart showing net book value over time. A "tax impact" toggle computes deferred tax differences between the methods (connecting to fiscal accounting concepts).

**Minimum viable inputs / outputs:**
- Inputs: asset cost, residual value, useful life (years), annual units (for units-of-production mode)
- Outputs: side-by-side depreciation schedules, cumulative depreciation chart, annual journal entries (6811/2818), total tax timing difference table
- Method selector: Linéaire (SL), Dégressif (DB at 1.5×/2×), Unités d'œuvre

**Why it complements existing playgrounds:** The existing playground is debt-amortization only. Asset depreciation uses different SYSCOHADA accounts and different economic logic. Keeping them separate avoids the very confusion this playground targets.
