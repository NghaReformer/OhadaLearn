### B-06 · LOW — `shadow-glow` in `tokens.ts` uses `var(--accent-glow)` self-reference before CSS custom property resolution
**File:** `src/lib/theme/tokens.ts:75` → `src/lib/theme/css-generator.ts` (emitted shadow)

`shadows.glow` is defined as `'0 0 20px var(--accent-glow)'` in the TypeScript object, then emitted verbatim as `--shadow-glow: 0 0 20px var(--accent-glow);`. This is a string containing a CSS variable reference that gets embedded inside another CSS variable. Browsers handle registered `var()` inside other `var()` values correctly, but this is fragile: if `--accent-glow` is overridden per-element, `--shadow-glow` will not pick it up. More practically, the `shadows` object in `ThemeTokens` is typed as raw strings but silently carries a dependency on the `colors.accentGlow` token.

**Suggested fix:** Either inline the resolved value in the TypeScript definition (e.g., derive `shadows.glow` programmatically from `colors.accentGlow`), or document the cross-token dependency explicitly.

### P-01 — VAT / TVA Return Calculator
**Title EN:** VAT Return Simulator  
**Title FR:** Simulateur de Déclaration de TVA

**Target learner:** Licence 2–3, practicing professional

**Pedagogical objective:** Fix the persistent misconception that TVA on purchases always creates a credit. Students mishandle partial deductibility (mixed-use assets, pro-rata calculation) and confuse `TVA collectée` with `TVA déductible`, leading to systematic errors in real-world filings. SYSCOHADA firms operate under OHADA-zone TVA regimes (18 % Senegal, 19.25 % Cameroon, etc.).

**Core interaction:** User enters a set of sales invoices (with or without TVA) and purchase invoices (full / partial deductibility toggles). The playground computes `TVA collectée`, `TVA déductible`, net position (credit or debit), and shows the journal entries for the TVA filing period. A regime selector lets learners switch between three OHADA-zone rates.

**Minimum viable I/O:**
- Inputs: list of sales lines (HT amount, TVA applicable Y/N), list of purchases (HT, deductibility %)
- Outputs: TVA summary table, net position, journal entry preview, filing deadline reminder

**Why it complements existing playgrounds:** Journal Entry handles day-to-day recording; this covers the periodic synthesis step. Together they model the full accounting cycle for indirect tax — a mandatory topic in every SYSCOHADA curriculum.

**Minimum viable I/O:**

- Outputs: three-step journal entry sequence with SYSCOHADA account codes, P&L impact per step, IFRS comparison toggle

**Why it complements existing playgrounds:** No existing playground touches foreign-currency accounting. This is a high-difficulty topic unique to OHADA-zone practice and directly maps to the `format/` currency system already in the codebase (`src/lib/format/`).
