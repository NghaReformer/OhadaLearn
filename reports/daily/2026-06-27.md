### MEDIUM-1 — Undefined CSS variables used across 10+ files (effective hardcoded colors)

**Severity:** High  
**Files:** `src/lib/components/playground/KpiStrip.svelte:76`, `src/lib/playgrounds/amortization/components/ScheduleTable.svelte:240,246,259`, `src/lib/playgrounds/amortization/components/InputsPanel.svelte:604–605`, `src/lib/playgrounds/amortization/components/ChartPanel.svelte:436,444,448,493,501,505,515,529,533`, `src/lib/playgrounds/bank-reconciliation/components/LedgerPanel.svelte:175`, `src/lib/playgrounds/bank-reconciliation/components/VarianceScale.svelte:230,260–261,331,335,370,416`, `src/lib/playgrounds/bank-reconciliation/components/TransactionJournal.svelte:382–383`, `src/lib/playgrounds/bank-reconciliation/components/BankStatementPanel.svelte:175`, `src/lib/playgrounds/bank-reconciliation/components/ScenarioWalkthrough.svelte:234,274`, `src/lib/playgrounds/bank-reconciliation/components/ReconciliationFlow.svelte:278`

**Explanation:** `--orange`, `--blue`, and `--red` are used as CSS custom properties throughout these components (e.g., `var(--orange, #f59e0b)`) but are **never defined** in `src/lib/theme/tokens.ts` or `src/lib/theme/css-generator.ts`. The fallback hex values therefore activate on every render, making these effectively hardcoded colors that bypass the theme system entirely. A future palette change (e.g., dark mode variant) will silently skip all these surfaces.

**Fix:** Add `orange`, `blue`, and `red` (or semantically named equivalents — `chartOrange`, `chartBlue`, `chartRed`) to the `ThemeTokens` interface in `tokens.ts`, assign values in `defaultTheme`, and emit the corresponding `--orange / --blue / --red` vars in `css-generator.ts`. Replace all `var(--red, ...)` usages with the appropriate semantic token — `--red` and `--error` currently coexist with inconsistent fallbacks (`#ef4444` vs `#f06070`), so consolidate error-state references to `var(--error)`.

### HIGH-2 — Bare hex strings in TypeScript color maps bypass theme entirely

**Severity:** High  
**Files:** `src/lib/playgrounds/bank-reconciliation/components/CategoryBreakdownDonut.svelte:31–39`, `src/lib/playgrounds/bank-reconciliation/components/MatchingPairsOverlay.svelte:31–34`

**Explanation:** Both files define TypeScript `Record<..., string>` objects mapping category/match types to hex strings (e.g., `'outstanding-check': '#6ea8fe'`, `fuzzy: '#f59e0b'`). Unlike the `var()` pattern above, these values are used directly in SVG stroke/fill attributes — they are completely outside the CSS cascade and cannot be overridden by theme tokens. The colours also partially overlap with existing tokens (`#6ea8fe` ≈ accent, `#f59e0b` ≈ amber) but are not the exact same values, creating visual inconsistency.

**Fix:** Replace each hex with the corresponding CSS token value read from a computed style lookup (e.g., `getComputedStyle(document.documentElement).getPropertyValue('--accent').trim()`) or, simpler, expose the color maps as CSS custom properties and reference them via `var()` in the SVG attributes.

### MEDIUM-4 — SSR renders `<html lang="en">` for all locales

**Severity:** Medium  
**File:** `src/app.html:2`

**Explanation:** The static HTML shell hardcodes `<html lang="en">`. The root layout does fix this client-side (`document.documentElement.lang = $locale` via `$effect`), but during SSR — the response sent to browsers and search engine crawlers — French pages (`/fr/...`) arrive with `lang="en"`. Screen readers and Google Search may apply incorrect linguistic processing to French content.

**Fix:** In `src/hooks.server.ts`, add a `handle` transformer that reads the URL path's leading segment (`/fr` vs `/en`), injects `lang="fr"` or `lang="en"` into the rendered HTML string before returning the response:
```ts
const lang = url.pathname.startsWith('/fr') ? 'fr' : 'en';
return new Response(body.replace('<html lang="en">', `<html lang="${lang}">`), response);
```

### IDEA-1 — Depreciation Methods (Native Svelte Module)

**Title (EN):** Depreciation Methods | **Title (FR):** Méthodes d'Amortissement Comptable  
**Target learner:** Licence 2  
**Pedagogical objective:** Students confuse economic depreciation (amortissement économique) with the three SYSCOHADA-approved book methods: linéaire, dégressif à taux variable, and unités de production. They also misapply the *prorata temporis* rule in year 1. A static HTML version already exists (`static/playgrounds/depreciation-playground.html`) but lacks exercises and learn-mode content.  
**Core interaction:** Learner inputs asset cost, useful life, residual value, and acquisition date; selects method; sees a live schedule table with year-end journal entries. Toggle between methods to compare total depreciation per period.  
**Minimum viable inputs:** Asset cost, useful life (years), acquisition date, residual value, method selector (linéaire / dégressif / unités-de-production + units per year).  
**Minimum viable outputs:** Full depreciation schedule (year, base, rate, charge, accumulated, net book value), journal entry preview per year, total fiscal impact.  
**Why it complements existing playgrounds:** Amortization playground covers **loan** amortization (constant payment schedules); this covers **asset** amortization/depreciation — a completely different concept that students often conflate.

### IDEA-2 — Working Capital Analysis (FRNG / BFRE / TN)

**Title (EN):** Working Capital Dashboard | **Title (FR):** Analyse du Fonds de Roulement  
**Target learner:** Licence 3  
**Pedagogical objective:** SYSCOHADA balance sheets expose FRNG (Fonds de Roulement Net Global), BFRE (Besoin en Fonds de Roulement d'Exploitation), and TN (Trésorerie Nette) as three interconnected metrics. Students routinely memorize formulas without understanding that TN = FRNG − BFRE and that a positive FRNG does not guarantee solvency. No existing playground covers working capital structure.  
**Core interaction:** Learner populates a simplified SYSCOHADA balance sheet (actif immobilisé, stocks, créances, trésorerie actif; capitaux propres, dettes financières LT, dettes d'exploitation, trésorerie passif). Three KPI cards update live (FRNG, BFRE, TN) with colour-coded status. A scenario mode lets learners stress-test by increasing supplier credit days or stock turnover.  
**Minimum viable inputs:** 8–10 balance sheet line items grouped by SYSCOHADA class.  
**Minimum viable outputs:** FRNG / BFRE / TN cards with sign and interpretation; waterfall decomposition chart; written interpretation sentence (localized EN/FR).  
**Why it complements existing playgrounds:** Bank Reconciliation teaches cash-book accuracy; this teaches **structural** cash position and financing policy — a higher-level analytical skill.

### IDEA-3 — SYSCOHADA Balance Sheet Builder

**Title (EN):** Balance Sheet Constructor | **Title (FR):** Constructeur de Bilan SYSCOHADA  
**Target learner:** Licence 2–3  
**Pedagogical objective:** Students can post journal entries (covered) but struggle to understand how accounts aggregate into the SYSCOHADA Bilan (classes 1–5) and Compte de Résultat (classes 6–7). The gap between individual entries and financial statements is a known sticking point before internship.  
**Core interaction:** Learner is given a randomized trial balance (15–20 accounts, pre-populated from chart-of-accounts data in `src/lib/shared/chart-of-accounts/`). They drag each account into the correct Bilan or CdR cell. On submit, the app shows the completed financial statements with totals and highlights misclassified items.  
**Minimum viable inputs:** Pre-generated trial balance (seeded); optional: learner can adjust amounts to explore impact.  
**Minimum viable outputs:** Two-column Bilan (actif / passif) and CdR (charges / produits), totals, balance check, animated reconciliation of net income across both statements.  
**Why it complements existing playgrounds:** Journal Entry teaches *how* to record transactions; this teaches *where those records end up* in financial statements — closing the loop of the accounting cycle.

### IDEA-4 — Payroll & Social Contributions Calculator (OHADA Zone)

**Title (EN):** Payroll & Social Charges | **Title (FR):** Bulletin de Paie et Charges Sociales  
**Target learner:** Licence 3, practicing professionals  
**Pedagogical objective:** OHADA-zone payroll is jurisdiction-specific: CNPS rates, IRPP (impôt sur le revenu) brackets, and family quotient rules differ between Cameroon, Côte d'Ivoire, Sénégal, etc. Students and junior accountants routinely compute net salary without accounting for the *part patronale* (employer contributions), leading to under-provisioned payroll charges.  
**Core interaction:** Learner selects country (Cameroon, Côte d'Ivoire, Sénégal — three jurisdictions as a first version), enters gross salary and number of dependents. The playground splits the result into take-home pay, salarié deductions (CNPS, IRPP), and patronale charges. A live journal entry shows the full payroll posting (débit Charges de Personnel + Charges Sociales / crédit Rémunérations dues + Organismes sociaux).  
**Minimum viable inputs:** Gross salary (FCFA), country selector, dependent count; toggle to show/hide employer portion.  
**Minimum viable outputs:** Net pay, deduction waterfall table, employer cost total, suggested journal entry.  
**Why it complements existing playgrounds:** Interest and TVM cover time value; this covers **labor cost accounting** — a core competency for any practicing professional in the OHADA zone that no current playground addresses.

### IDEA-5 — Financial Ratio Dashboard (Diagnostic Financier)

**Title (EN):** Financial Ratio Analyzer | **Title (FR):** Tableau de Bord des Ratios Financiers  
**Target learner:** Licence 3, Master, practicing professionals  
**Pedagogical objective:** Students can read a balance sheet but cannot synthesize it into a credit or management diagnosis. They conflate liquidity ratios (liquidité générale, liquidité immédiate) with solvency ratios (autonomie financière, capacité de remboursement) and profitability ratios (ROE, ROA, marge nette). SYSCOHADA-specific ratios like capacité d'autofinancement (CAF) are rarely taught interactively.  
**Core interaction:** Learner inputs a simplified balance sheet + P&L (or loads one of two pre-built scenarios — "PME saine" vs "entreprise en difficulté"). The dashboard displays 10 computed ratios across four families with colour-coded thresholds and one-sentence plain-language interpretation per ratio. Learner can adjust individual line items and watch ratios recompute.  
**Minimum viable inputs:** 12–15 aggregated financial statement lines (not raw accounts); scenario loader for two pre-built examples.  
**Minimum viable outputs:** Ratio table (name, formula, value, benchmark, status badge), spider/radar chart across the four families, a one-paragraph overall diagnosis (generated from rule-based interpretation logic, not LLM).  
**Why it complements existing playgrounds:** CVP playground covers internal cost-volume decisions; this covers **external financial diagnosis** — the analytical lens used by banks, auditors, and investors in the OHADA zone.
