### [HIGH] Undefined CSS custom properties `--orange`, `--blue` used in 24+ locations

**Files (sample):**
- `src/lib/components/playground/KpiStrip.svelte:76`
- `src/lib/playgrounds/amortization/components/ChartPanel.svelte:436,444,493,501,515,529,533`
- `src/lib/playgrounds/amortization/components/ScheduleTable.svelte:240,246`
- `src/lib/playgrounds/bank-reconciliation/components/LedgerPanel.svelte:175`
- `src/lib/playgrounds/bank-reconciliation/components/VarianceScale.svelte:230,260,261,331,335,370,416`
- `src/lib/playgrounds/bank-reconciliation/components/TransactionJournal.svelte:382,383`
- `src/lib/playgrounds/bank-reconciliation/components/ScenarioWalkthrough.svelte` (multiple)
- `src/lib/playgrounds/bank-reconciliation/components/ReconciliationFlow.svelte:278`

**Explanation:** These components use the pattern `var(--orange, #f59e0b)` and `var(--blue, #3b82f6)` throughout chart and table styles. However, `--orange` and `--blue` are never emitted by `src/lib/theme/css-generator.ts` (verified: the generator only emits `--green`, `--amber`, `--accent`, `--error` and their variants). The CSS variable lookup silently fails on every render, and the browser falls back to the hardcoded hex. The theme system is completely bypassed for these colors — a future accent/color update would not affect them.

**Suggested fix:** Add `orange`, `blue` (and any other semantic chart colors) to `ThemeTokens` in `tokens.ts`, populate them in `defaultTheme`, and emit `--orange: ${c.orange}; --blue: ${c.blue};` in `css-generator.ts`. The fallback values already in use make the correct defaults obvious.

### [HIGH] Hardcoded hex color maps in JavaScript — completely outside theme system

**Files:**
- `src/lib/playgrounds/bank-reconciliation/components/CategoryBreakdownDonut.svelte:30–39`
- `src/lib/playgrounds/bank-reconciliation/components/MatchingPairsOverlay.svelte:30–35`

**Explanation:** Both components define TypeScript `const` objects mapping category/match-type keys to hardcoded hex strings (e.g., `'outstanding-check': '#6ea8fe'`, `fuzzy: '#f59e0b'`). These strings are passed directly to SVG `stroke`/`fill` attributes, not via CSS. No CSS custom property or theme token is involved — these colors cannot be restyled by a theme change and will never respect dark/light mode switching if it is added later.

**Suggested fix:** Derive colors from the theme token semantic set. Where the theme already has a close match (accent → `#6ea8fe`, green → `#22c55e`, amber → `#f59e0b`, error → `#ef4444`), pass `getComputedStyle(document.documentElement).getPropertyValue('--accent')` or map to a CSS class that applies the stroke via a `<style>` block using theme vars. Alternatively, add named chart-palette tokens to the theme.

### [MEDIUM] `color: #fff` hardcoded on active button states — missing `--text-on-accent` token

**Files:**
- `src/lib/playgrounds/journal-entry/components/EntryHistory.svelte:400` (`.btn-confirm`)
- `src/routes/[lang]/chart-of-accounts/+page.svelte:423` (`.framework-btn.active`)
- `src/routes/[lang]/chart-of-accounts/+page.svelte:458` (`.class-chip.active`)
- `src/routes/[lang]/learn/+page.svelte:202` (`.group-cta`)

**Explanation:** Each active/CTA element sets `background: var(--accent)` or `background: var(--error)` then `color: #fff`. The theme token system has no `--text-on-accent` token, so authors fell back to `#fff`. This creates a fragile contract: if `--accent` is ever changed to a light color, contrast will break silently with no theme-level control.

**Suggested fix:** Add `textOnAccent: '#ffffff'` to `ThemeTokens` / `defaultTheme`, emit `--text-on-accent: ${c.textOnAccent};` in `css-generator.ts`, and replace the four `color: #fff` instances with `color: var(--text-on-accent)`.

### Idea 1 — Working Capital Analysis / Analyse du Fonds de Roulement (FR–BFR–TN)

**Title EN:** Working Capital Analyzer  
**Title FR:** Analyseur du Fonds de Roulement

**Target learner:** Licence 2 / Licence 3

**Pedagogical objective:** Students routinely confuse the three SYSCOHADA working capital metrics and fail to interpret the TN (Trésorerie Nette) sign correctly. This playground forces them to construct each metric from balance sheet items and diagnose what the results imply for a firm's financial health — a staple of SYSCOHADA final exams.

**Core interaction:** The learner fills in a simplified bilan (long-term assets/equity/LT liabilities on one side; current assets/current liabilities on the other). The playground computes FR = Capitaux permanents − Actif immobilisé, BFR = (Stocks + Créances) − Dettes d'exploitation, TN = FR − BFR in real time. A visual balance bar animates as inputs change, and a diagnostic panel explains whether the firm is structurally sound, over-trading, or cash-starved.

**Minimum viable inputs/outputs:**
- Inputs: actif immobilisé, stocks, créances clients, autres actifs courants, capitaux propres, dettes financières LT, dettes fournisseurs, autres dettes courantes
- Outputs: FR, BFR, TN (computed live), interpretation badge (positive/negative/zero for each), delta-sensitivity sliders ("what if receivables grow 20%?")

**Why it complements existing playgrounds:** Bank reconciliation checks that cash records agree; this playground checks whether the *level* of cash is structurally sustainable. CVP addresses operational break-even; FR–BFR–TN addresses financial structure. Together they cover both the P&L and the balance sheet dimension.

### Idea 2 — Fixed Asset Depreciation Methods / Amortissement des Immobilisations

**Title EN:** Depreciation Methods Comparator  
**Title FR:** Comparateur de Méthodes d'Amortissement

**Target learner:** Licence 1 / Licence 2

**Pedagogical objective:** The existing amortization playground handles loan repayment schedules. SYSCOHADA Article 45 requires firms to account for *fixed-asset* depreciation (linéaire, dégressif, unités de production), and students regularly confuse the two concepts. This playground isolates that gap.

**Core interaction:** The learner enters an asset (cost, residual value, useful life, acquisition date). Tabs switch between the three SYSCOHADA-permitted methods. A side-by-side table shows the annual charge, accumulated depreciation, and net book value for each method simultaneously, so the impact on reported profit is immediately visible.

**Minimum viable inputs/outputs:**
- Inputs: cost, residual value, useful life (years), degressive coefficient (0.75/1.0/1.25/1.5 per SYSCOHADA scale), production capacity + actual units per year (for units-of-production)
- Outputs: schedule table (annuité, amortissement cumulé, VNC), comparative chart, journal entries for year-1 (Dotations aux amortissements / Amortissements de l'immobilisation)

**Why it complements existing playgrounds:** The existing amortization playground models financial loan schedules. This addresses the entirely different SYSCOHADA accounting treatment for tangible/intangible assets.

### Idea 3 — Inventory Valuation / Évaluation des Stocks (FIFO vs CMUP)

**Title EN:** Inventory Valuation Methods  
**Title FR:** Méthodes d'Évaluation des Stocks

**Target learner:** Licence 2

**Pedagogical objective:** Under SYSCOHADA Articles 37–39, only FIFO and weighted-average cost (CMUP — Coût Moyen Unitaire Pondéré) are permitted. Students memorise the formulas but fail to see how the *same* physical inventory produces different reported COGS, ending stock value, and tax impact depending on the method chosen.

**Core interaction:** The learner builds a chronological log of stock movements (entries with quantity + unit cost, exits with quantity only). The playground computes FIFO and CMUP schedules side by side, highlighting the period where results diverge most strongly. A "price trend" selector (rising / falling / volatile) re-orders the entries to show when method choice matters most.

**Minimum viable inputs/outputs:**
- Inputs: opening stock (qty + unit cost), sequence of entrées (qty + unit cost) and sorties (qty), period (month/year)
- Outputs: FIFO valuation table (cost of each batch consumed), CMUP table (rolling or periodic), ending stock value comparison, COGS comparison, effect on gross margin

**Why it complements existing playgrounds:** No existing playground touches stock accounting. Journal entry playground can record the entries once students understand the valuation; this playground supplies the valuation the journal entry depends on.

### Idea 4 — TVA / VAT Journal Entries / Comptabilisation de la TVA

**Title EN:** VAT Accounting Entries  
**Title FR:** Comptabilisation de la TVA

**Target learner:** Licence 1 / Licence 2

**Pedagogical objective:** Recording VAT correctly is the single most common error in Licence 1 examinations across OHADA zone. Students confuse TVA collectée (compte 4431) with TVA déductible (compte 4441) and routinely record net amounts when gross amounts are required. This playground closes that gap with immediate visual feedback.

**Core interaction:** The learner selects a country (Cameroun 19.25%, Sénégal 18%, Côte d'Ivoire 18%, others) to set the rate. They then input purchase and sale transactions (HT amounts). The playground generates the required journal entries with the correct SYSCOHADA account codes, shows the TVA position (solde de TVA à décaisser ou à récupérer), and lets the learner attempt to write the entries themselves before revealing the answer.

**Minimum viable inputs/outputs:**
- Inputs: country/TVA rate, HT amount, transaction type (vente / achat / importation / exportation exonérée)
- Outputs: journal entry with accounts 401, 411, 4431, 4441, 707/607, TVA balance, monthly declaration summary

**Why it complements existing playgrounds:** Journal entry playground teaches debit/credit mechanics. TVA playground applies those mechanics to the most frequent real-world compliance requirement in OHADA zone, grounding the abstract skill in a concrete tax context.

### Idea 5 — Financial Ratios Dashboard / Tableau de Bord des Ratios

**Title EN:** Financial Ratios Dashboard  
**Title FR:** Tableau de Bord des Ratios Financiers

**Target learner:** Licence 3 / Master / practicing professional

**Pedagogical objective:** Students can compute individual ratios from a formula sheet but struggle to interpret them holistically or to diagnose which ratio signals a real problem versus a structural feature of the industry. This playground builds the diagnostic habit.

**Core interaction:** The learner inputs a simplified bilan and compte de résultat. The playground computes the standard SYSCOHADA ratio set — autonomie financière, capacité de remboursement, liquidité générale/réduite/immédiate, rentabilité économique (ROCE), rentabilité financière (ROE), délai de rotation clients/fournisseurs/stocks — and renders them as a radar chart and ranked scorecard. A "sector benchmark" selector (commerce, industrie, services) sets the green/amber/red thresholds.

**Minimum viable inputs/outputs:**
- Inputs: capitaux propres, total dettes, actif total, actif courant, stocks, créances clients, dettes fournisseurs, CA, résultat net, EBE, dettes financières
- Outputs: 10-12 computed ratios with status indicator, radar chart comparing firm vs sector benchmark, one-line commentary per ratio, drill-down to show the formula used

**Why it complements existing playgrounds:** CVP and FR–BFR–TN (proposed above) each show one slice of financial health. The ratios dashboard synthesises all slices into an integrated portrait — the analytical skill expected at Licence 3 level and in professional certification.
