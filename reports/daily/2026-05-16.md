## 1. Bugs & Issues

### BUG-01 — `onMount` used instead of `$effect` (Svelte 5 violation)
- **Severity:** Medium
- **File:** `src/lib/components/feedback/FeedbackLauncher.svelte:2,12–24`
- **Explanation:** `onMount` is a Svelte 4 lifecycle hook. CLAUDE.md mandates runes-only; the equivalent runes pattern is `$effect`. The `mounted` guard (line 8, 31) is also redundant when using `$effect`, since effects run after mount automatically.
- **Suggested fix:** Replace `onMount` with `$effect`; the cleanup return value is already supported. Remove the `mounted` state flag and the `{#if mounted}` wrapper — use CSS `visibility` or `opacity` if a flash-of-content guard is needed.

### BUG-02 — Hardcoded `rgba(0, 0, 0, 0.3)` outside design tokens
- **Severity:** Medium
- **File:** `src/lib/components/PlaygroundCard.svelte:45`
- **Explanation:** `box-shadow: 0 8px 30px rgba(0, 0, 0, 0.3), var(--shadow-glow)` hardcodes a color value. All color decisions must live in `src/lib/theme/tokens.ts` and be consumed as CSS custom properties. If the theme ever switches to a lighter variant, this value will not update.
- **Suggested fix:** Add a `--shadow-dark` token to `tokens.ts` (e.g. `rgba(0, 0, 0, 0.3)`) and reference `var(--shadow-dark)` in the component.

### BUG-03 — User-facing string not routed through i18n
- **Severity:** Medium
- **File:** `src/routes/[lang]/+page.svelte:28`
- **Explanation:** `<span class="hero-badge">SYSCOHADA Revisé 2017</span>` is a hardcoded French/English hybrid string. It violates the i18n rule: all user-facing text must go through the `t()` system with EN/FR parity.
- **Suggested fix:** Add `landing.hero.badge` key to `landing.en.ts` (`"SYSCOHADA Revisé 2017"`) and `landing.fr.ts` (same value or a localized variant), then replace the markup with `{$t('landing.hero.badge')}`.

### BUG-04 — Missing role enum validation in waitlist API
- **Severity:** High
- **File:** `src/routes/api/waitlist/+server.ts:58`
- **Explanation:** The `role` field passes through presence-only validation (line 38) and is inserted into Supabase verbatim (line 58). The frontend `<select>` constrains values to `student | instructor | professional | other`, but the API accepts any arbitrary string — bypassing the client is trivial with a direct POST.
- **Suggested fix:** Add a server-side allowlist check before the `insertEntry` call:
  ```ts
  const ALLOWED_ROLES = ['student', 'instructor', 'professional', 'other'];
  if (!ALLOWED_ROLES.includes(body.role)) {
    return json({ error: 'Invalid role' }, { status: 400 });
  }
  ```

### BUG-05 — Double-quoted object keys break i18n key-extraction scripts
- **Severity:** Medium
- **File:** `src/lib/i18n/namespaces/common.fr.ts:61–62`
- **Explanation:** Keys `"coa.class.6"` and `"coa.class.7"` use double quotes while every other key in the file (and all other namespace files) uses single quotes. The `i18n:check` script likely uses a regex anchored to single-quote key syntax. These two keys will be invisible to the extractor, causing a reported mismatch even though the keys are present at runtime.
- **Suggested fix:** Change lines 61–62 to single-quoted keys: `'coa.class.6': "Charges d'exploitation"`.

### BUG-06 — Sequential `await` inside `for` loops in two server load functions
- **Severity:** Medium
- **Files:**
  - `src/routes/[lang]/learn/+page.server.ts:19–28`
  - `src/routes/[lang]/scenarios/+page.server.ts:16–27`
- **Explanation:** Both loaders iterate over all registered playgrounds (currently 6) with a sequential `await` per iteration. Each call hits the filesystem (or Supabase). With 6 playgrounds the latency is ~6× the single-call cost, and it will scale linearly as content grows.
- **Suggested fix:** Replace with `Promise.all`:
  ```ts
  const results = await Promise.all(playgrounds.map(pg => loadLearnSections(pg.slug, locale)));
  const groups = results.flatMap((sections, i) => sections.length === 0 ? [] : [{ ...playgrounds[i], sections: sections.sort(...) }]);
  ```

### BUG-07 — Hardcoded `60px` nav-height magic number in 4 route files
- **Severity:** Low
- **Files:**
  - `src/routes/[lang]/chart-of-accounts/+page.svelte:247`
  - `src/routes/[lang]/playgrounds/[slug]/+page.svelte:142`
  - `src/routes/[lang]/scenarios/+page.svelte:100`
  - `src/routes/[lang]/learn/+page.svelte:87`
- **Explanation:** All four files use `calc(100vh - 60px)` to subtract the navbar height. This is a magic number duplicated across four places with no shared token. If the nav height changes, all four sites break silently.
- **Suggested fix:** Add `--nav-height: 60px` to the root CSS (or token system) and replace every occurrence with `calc(100vh - var(--nav-height))`.

### BUG-08 — `feedback.fr.ts` is 3 lines longer than `feedback.en.ts` (silent parity drift)
- **Severity:** Low
- **Files:** `src/lib/i18n/namespaces/feedback.en.ts` (58 lines) vs `feedback.fr.ts` (61 lines)
- **Explanation:** The line-count difference (3 lines) suggests either extra keys, extra comments, or formatting differences in the FR file. The `i18n:check` script should catch actual key mismatches, but the difference warrants manual inspection — a stale key left only in the FR file will never be reported missing, only unused.
- **Suggested fix:** Run `npm run i18n:check` and verify output; if all keys match, add a comment explaining the line difference.

## 2. New Playground Ideas

Existing playgrounds cover: journal entry posting, time value of money (TVM), cost-volume-profit (CVP), loan amortization, interest calculations, and bank reconciliation. The four static HTML iframes cover amortization, CVP, depreciation (fixed-asset), and journal entry at a simpler level.

---

### PG-01 — Payroll & Social Charges Calculator
**Title (EN):** OHADA Payroll Workbench  
**Title (FR):** Atelier de Paie OHADA

**Target learner:** Licence 3 / Master 1, practicing HR/accounting professionals

**Pedagogical objective:** Most SYSCOHADA learners misunderstand the distinction between gross pay, employer social charges, and employee deductions. They conflate "cost to employer" with "net salary" and struggle to trace how CNPS, IRPP, and professional taxes flow to separate liability accounts (431, 432, 447).

**Core interaction:** The learner enters: employee category, gross salary, number of taxable allowances, and applicable convention collective (OHADA zone country selector). The playground computes: employer cost breakdown, employee deductions, net-to-pay, and generates the journal entry to post (Classe 6 wages expense, Classe 4 liability accounts). A toggle shows the payslip view vs. the accounting entry view.

**Minimum viable inputs / outputs:**
- Inputs: gross salary, country (Cameroun / Côte d'Ivoire / Sénégal / generic), bonus amounts, number of dependents
- Outputs: CNPS employer share, CNPS employee share, IRPP withholding, professional tax, net salary, full double-entry journal

**Why it complements existing playgrounds:** Journal Entry teaches posting mechanics but uses simplified amounts. This playground grounds a real, high-frequency payroll transaction in SYSCOHADA account codes, bridging the journal-entry playground to real practice.

---

### PG-02 — Financial Ratio Analyser
**Title (EN):** Financial Ratio Dashboard  
**Title (FR):** Tableau de Bord des Ratios Financiers

**Target learner:** Licence 2 / Licence 3, Master 1

**Pedagogical objective:** Learners memorise ratio formulas but cannot interpret them in context. They do not understand how a single balance-sheet decision (e.g. taking on short-term debt to fund inventory) simultaneously degrades the current ratio and improves asset turnover.

**Core interaction:** The learner is presented with a simplified SYSCOHADA bilan (balance sheet) and compte de résultat (income statement) with editable cells for key line items. The playground computes 10–12 ratios live (liquidity, solvency, profitability, activity), colour-codes each against sector benchmarks, and draws a radar chart. When the learner adjusts a cell, they see which ratios move and why.

**Minimum viable inputs / outputs:**
- Inputs: actifs circulants, trésorerie, dettes à court terme, chiffre d'affaires, résultat net, capitaux propres, total actif, stocks
- Outputs: current ratio, quick ratio, debt-to-equity, ROE, ROA, net margin, asset turnover, DSO — with sector-benchmark overlays

**Why it complements existing playgrounds:** CVP focuses on cost structure; this playground focuses on the resulting financial position and health metrics. TVM shows discounting; this shows what those discounted cash flows imply for investor ratios.

### PG-03 — VAT / TVA Return Builder
**Title (EN):** VAT Return Workbench  
**Title (FR):** Atelier de Déclaration TVA

**Target learner:** Licence 3 / Master, practicing accountants

**Pedagogical objective:** Students confuse TVA collectée (output VAT) with TVA déductible (input VAT) and make systematic errors in computing TVA à décaisser. They also misclassify mixed-use purchases and exempt supplies, leading to wrong credit-carry-forward amounts.

**Core interaction:** The learner inputs a list of 5–8 purchase and sale transactions (with amounts HT and TVA rate), categorises each as fully taxable / partially exempt / fully exempt, and the playground builds the TVA return: collectée, déductible, TVA nette, and the resulting account 443 / 445 journal entry. A common-mistake mode presents pre-filled erroneous returns for the learner to diagnose.

**Minimum viable inputs / outputs:**
- Inputs: list of transactions (description, HT amount, TVA rate, direction buy/sell, exempt flag)
- Outputs: TVA collectée subtotal, TVA déductible subtotal, TVA nette à payer (or credit), declaration summary grid, journal entry for compte 443/4431/4452

**Why it complements existing playgrounds:** Bank Reconciliation handles the cash/bank-statement side; this playground handles the VAT-account side — together they cover the two most common monthly accounting close tasks.

### PG-04 — Cash Flow Statement Builder (Indirect Method)
**Title (EN):** Cash Flow Statement — Indirect Method  
**Title (FR):** Tableau de Flux de Trésorerie — Méthode Indirecte

**Target learner:** Master 1 / Master 2, practicing consolidation accountants

**Pedagogical objective:** Students treat the cash flow statement as a black box output rather than a reconciliation. They cannot explain why net income and operating cash flow diverge, or trace how a change in accounts receivable creates a cash outflow that doesn't appear on the income statement.

**Core interaction:** The learner is given a two-year comparative bilan and a compte de résultat. They must classify and drag balance-sheet movements into the three sections (operating, investing, financing), adjust for non-cash charges (amortissement, provisions), and arrive at the closing cash balance. The playground validates each line placement and highlights errors in real time.

**Minimum viable inputs / outputs:**
- Inputs: résultat net, amortissements, variation créances, variation stocks, variation dettes fournisseurs, acquisitions immobilisations, emprunts émis/remboursés
- Outputs: flux exploitation, flux investissement, flux financement, variation de trésorerie, trésorerie clôture — reconciled to balance-sheet cash account

**Why it complements existing playgrounds:** TVM teaches discounting future cash flows; this playground teaches how to construct the cash flow statement those valuations depend on — a natural pedagogical bridge.

### PG-05 — Fixed-Asset Register & Depreciation Scheduler
**Title (EN):** Fixed-Asset Register  
**Title (FR):** Registre des Immobilisations

**Target learner:** Licence 2 / Licence 3

**Pedagogical objective:** The static HTML `depreciation-playground.html` covers the depreciation formula in isolation. Learners do not connect it to the full asset lifecycle: acquisition posting (Classe 2), annual depreciation expense (Classe 6) and accumulated depreciation (Classe 28), partial-year proration, and disposal gain/loss calculation (Classe 7/8).

**Core interaction:** The learner adds assets to a register (name, account code from Classe 2 picker, acquisition cost, date, useful life, residual value, depreciation method — linear or dégressif). The playground generates: the full depreciation schedule, cumulative book value chart, and the journal entries for each year — including a disposal scenario where the learner enters a sale price and the playground computes profit or loss on disposal.

**Minimum viable inputs / outputs:**
- Inputs: asset name, Classe 2 account code, cost, acquisition date, useful life (years), residual value, method (linear / dégressif), optional disposal date and sale price
- Outputs: year-by-year depreciation table, book value chart, journal entries per year, disposal gain/loss entry

**Why it complements existing playgrounds:** The existing `depreciation-playground.html` is a static iframe with no lifecycle awareness. This native Svelte playground extends it with the full accounting lifecycle, using the shared `AccountPicker` component for SYSCOHADA account codes and the `format/` system for currency display.
