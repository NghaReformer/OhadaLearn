### [HIGH] Hardcoded `color: #fff` — 4 locations

Per CLAUDE.md: "All colors/fonts/spacing via CSS custom properties from theme tokens — NEVER hardcode hex colors."

These four rules apply `#fff` directly for text-on-colored-background scenarios, bypassing the theme system entirely. If the theme ever introduces a light-mode variant or re-tones the accent, these will silently produce unreadable text.

| Severity | File | Line | Context |
|----------|------|------|---------|
| HIGH | `src/lib/playgrounds/journal-entry/components/EntryHistory.svelte` | 400 | `.btn-confirm { color: #fff; }` |
| HIGH | `src/routes/[lang]/chart-of-accounts/+page.svelte` | 423 | `.framework-btn.active { color: #fff; }` |
| HIGH | `src/routes/[lang]/chart-of-accounts/+page.svelte` | 458 | `.class-chip.active { color: #fff; }` |
| HIGH | `src/routes/[lang]/learn/+page.svelte` | 202 | `.group-cta { color: #fff; }` |

**Suggested fix:** Add a `--text-on-accent` token (value `#ffffff` for the dark theme) to `src/lib/theme/tokens.ts`, then replace all four instances with `color: var(--text-on-accent)`. This makes the intent explicit and keeps the override point in one place.

### [MEDIUM] Hardcoded hex fallback inside `var()` — KpiStrip.svelte:76

`src/lib/components/playground/KpiStrip.svelte:76`

```css
color: var(--orange, #f59e0b);
```

The `#f59e0b` fallback is unreachable if `tokens.ts` always emits `--orange`, but it violates the no-hardcoded-hex rule and will silently activate if the token is ever renamed.

**Suggested fix:** Remove the fallback — `color: var(--orange)` — since `--orange` is defined unconditionally in `css-generator.ts`. If a fallback is desired, reference another token: `var(--orange, var(--accent))`.

### [MEDIUM] Deprecated `document.execCommand('copy')` — ShareButton.svelte:22

`src/lib/components/playground/ShareButton.svelte:22`

```js
document.execCommand('copy');
```

`execCommand` is removed from the living HTML spec and flagged as deprecated in all major browsers. The surrounding guard `if (navigator.clipboard && window.isSecureContext)` already handles modern contexts. The fallback branch is only reached in non-secure contexts (plain HTTP), which Vercel never serves in production.

**Suggested fix:** Remove the `else` branch entirely. If offline/HTTP support must be retained, replace `execCommand` with a `<textarea>` + `select()` approach using the Selection API, or display the URL in a modal for manual copying.

### Idea 1 — Working Capital Analyser / Analyseur du Besoin en Fonds de Roulement

**Title (EN):** Working Capital Analyser  
**Title (FR):** Analyseur du BFR (Besoin en Fonds de Roulement)

**Target learner:** Licence 2 / Licence 3

**Pedagogical objective:** Students consistently confuse FRNG (Fonds de Roulement Net Global), BFR, and trésorerie nette. The equilibrium `Trésorerie = FRNG − BFR` is stated in textbooks but rarely made tangible. This playground forces students to manipulate the balance-sheet items that drive each component and observe the cascading effect.

**Core interaction:** The learner adjusts sliders for: accounts receivable days, inventory days, accounts payable days, and fixed-asset financing. Three live gauges update — FRNG, BFR, Trésorerie nette — color-coded green/amber/red. A fourth panel shows whether the firm is in "BFR positif" (needs financing) or "BFR négatif" (operating credit from suppliers), with the SYSCOHADA class-4 and class-5 accounts highlighted.

**Minimum viable inputs:** Receivable days (DSO), inventory days (DIO), payable days (DPO), current assets total, current liabilities total, permanent capital, fixed assets.  
**Outputs:** FRNG, BFR, Trésorerie nette, classification (favorable / défavorable), suggested action (reduce stocks, renegotiate supplier terms).

**Why it complements existing playgrounds:** The Journal Entry playground handles individual transaction recording; this playground zooms out to the structural health of the balance sheet. Scenarios could pre-load a journal-entry session's running trial balance, making the two playgrounds composable.

### Idea 2 — SYSCOHADA Financial Ratios Dashboard / Tableau de Bord des Ratios Financiers

**Title (EN):** Financial Ratios Dashboard  
**Title (FR):** Tableau de Bord des Ratios Financiers SYSCOHADA

**Target learner:** Licence 3 / Master

**Pedagogical objective:** SYSCOHADA-trained students know individual ratio formulas but rarely see the full picture — how a change in one line item ripples across solvency, profitability, and activity ratios simultaneously. This playground replaces drilling formulas with understanding interdependencies.

**Core interaction:** The learner is given a pre-populated SYSCOHADA balance sheet + income statement (matching OHADA account class structure). Editing any line item in a side-by-side input panel instantly recomputes ~12 ratios grouped into four SYSCOHADA-standard families: liquidité, structure financière, rentabilité, activité. Each ratio tile shows the formula, the computed value, and a benchmark band (e.g., current ratio > 1.0 = green).

**Minimum viable inputs:** 8–10 balance-sheet line items (grouped by SYSCOHADA class), 4–5 P&L line items.  
**Outputs:** Ratio grid (12 ratios), spider chart showing the firm's profile, narrative summary ("Entreprise sur-endettée, rentabilité correcte, liquidité insuffisante").

**Why it complements existing playgrounds:** The Chart of Accounts playground provides the account taxonomy; this playground shows what those numbers mean at the aggregate level.

### Idea 3 — TAFIRE Builder / Constructeur du Tableau des Flux de Trésorerie

**Title (EN):** Cash Flow Statement Builder (TAFIRE)  
**Title (FR):** Constructeur du TAFIRE (Tableau de Financement)

**Target learner:** Licence 3 / Master / Practicing professional

**Pedagogical objective:** The TAFIRE (Tableau de Financement par les Ressources et Emplois) is the SYSCOHADA cash-flow statement and is notoriously hard to prepare manually. Students confuse which movements are operating vs. investing vs. financing, and where the indirect method adjustments go (reintégration des amortissements, variation du BFR).

**Core interaction:** The learner drags journal entries (or picks them from the Journal Entry playground's history export) into one of three buckets: Exploitation, Investissement, Financement. The playground validates the classification against SYSCOHADA rules, computes subtotals, and reconciles to the opening/closing cash position. Misclassified entries are highlighted with a one-line explanation of the correct bucket.

**Minimum viable inputs:** List of transactions with amounts and SYSCOHADA account codes (pre-loaded from a scenario or entered manually), opening cash balance.  
**Outputs:** Full TAFIRE in OHADA-standard format, variance from opening cash, validation errors.

**Why it complements existing playgrounds:** This is the natural capstone after Journal Entry — students record entries, then learn how those same entries translate into cash-flow reporting. The contracts/playground.ts `PlaygroundModule` interface supports cross-playground scenario loading.

### Idea 4 — VAT Recorder / Journal de TVA

**Title (EN):** VAT Recorder  
**Title (FR):** Journal de TVA (Taxe sur la Valeur Ajoutée)

**Target learner:** Licence 1 / Licence 2

**Pedagogical objective:** Many OHADA-zone countries apply a 18–19.25% TVA. Beginners confuse deductible TVA (compte 4452 — asset for the firm) with collected TVA (compte 4431 — liability), and mispost net-vs-gross amounts. This playground makes the double-sided VAT position visible before they encounter it in a full journal entry.

**Core interaction:** The learner inputs: transaction type (purchase or sale), gross amount, VAT rate. The playground decomposes the gross into net + TVA, shows which SYSCOHADA accounts move (401/411, 4431/4452, 601-series/701-series), and displays the net VAT position (TVA à décaisser = 4431 − 4452). A second mode lets the learner build a mini VAT declaration for a period (monthly totals).

**Minimum viable inputs:** Transaction direction, gross amount, VAT rate (0 / 10 / 18 / 19.25 %), accounting period.  
**Outputs:** Journal line decomposition, running TVA position, VAT declaration stub.

**Why it complements existing playgrounds:** The Journal Entry playground assumes the user knows the correct accounts; this playground teaches why accounts 4431/4452 are used, serving as prerequisite scaffolding.

### Idea 5 — Payroll Calculator / Bulletin de Paie OHADA

**Title (EN):** Payroll Calculator (OHADA)  
**Title (FR):** Calculateur de Bulletin de Paie (Zone OHADA)

**Target learner:** Master / Practicing professional

**Pedagogical objective:** SYSCOHADA payroll accounting requires booking gross salary (compte 661), social-security contributions split between employer and employee (comptes 431/432), IRPP withholding (compte 447), and the net-payable liability (compte 422). Getting these decompositions right under OHADA labor conventions is an error-prone workflow even for professionals.

**Core interaction:** The learner enters: country (Cameroun, Côte d'Ivoire, Sénégal, etc.), gross monthly salary, job category. The playground applies the country's CNPS/CNSS contribution rates and IRPP bracket table, produces a formatted bulletin de paie, and then shows the SYSCOHADA journal entries the employer must book — both for salary cost and for the payment run.

**Minimum viable inputs:** Country, gross salary, employee category (cadre / non-cadre), family allowance charges, optional overtime.  
**Outputs:** Net salary, employer cost, contribution breakdown, SYSCOHADA journal entries (661, 431, 432, 447, 422), downloadable bulletin template.

**Why it complements existing playgrounds:** No existing playground touches the human-resources → accounting interface. Payroll is one of the most common real-world entries for OHADA-zone companies, and the multi-country angle makes this platform differentiating for university programs that cover the full OHADA zone.
