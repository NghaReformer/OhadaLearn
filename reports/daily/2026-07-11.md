**File:** `src/lib/finance/dayCount.ts:7`

`yearFraction` has a `switch` over `DayCount` without a `default` clause. TypeScript reports `TS2366: Function lacks ending return statement`. #### H-2 · `src/lib/components/feedback/FeedbackForm.svelte:7` · Server-boundary `import type` from `$lib/server/`
**Severity:** High  
**File:** `src/lib/components/feedback/FeedbackForm.svelte:7`

```ts
import type { FeedbackType, FeedbackSeverity } from '$lib/server/db/types';
```

`FeedbackForm.svelte` is a client component that imports types from `$lib/server/db/types`. While `import type` is erased at runtime, SvelteKit's Vite plugin enforces the `$lib/server/` boundary statically and can flag this during build. The shared types `FeedbackType` and `FeedbackSeverity` are pure string unions with no server-only dependencies.

**Fix:** Move `FeedbackType` and `FeedbackSeverity` to `src/lib/shared/types.ts` (or `src/lib/contracts/feedback.ts`) and import from there.

#### H-3 · `src/lib/playgrounds/cvp/components/GoalSeekPanel.svelte:43-47` · `$effect` does not re-initialize on prop change
**Severity:** High  
**File:** `src/lib/playgrounds/cvp/components/GoalSeekPanel.svelte:43`

```ts
$effect(() => {
    if (targetProfitInput === '') {
        targetProfitInput = fmtNumber(targetProfit || 20000, 0, locale);
    }
});
```

This effect tracks `targetProfit` and `locale` reactively, but only writes when `targetProfitInput === ''`. If the parent scenario changes `targetProfit`, the input field is never updated (because it's already non-empty). The solver will run against stale data while displaying fresh scenario values.

**Fix:** Reset `targetProfitInput` whenever `targetProfit` changes, not only when empty. Use `$effect` with a separate initialization: track the previous `targetProfit` value and reset when it changes.

### Idea A — VAT / Sales Tax Register
**Title (EN):** VAT Register & Returns  
**Title (FR):** Grand livre TVA & Déclaration  
**Target learner:** Licence 2–3, practicing professional  
**Pedagogical objective:** Students consistently confuse collectible TVA (collected on sales) vs. deductible TVA (paid on purchases), and miscalculate the net TVA payable. This playground makes the split visible and lets learners build a complete monthly return.

**Core interaction:** Learner enters a list of purchase and sale transactions. The playground maintains a live TVA register (TVA collectée, TVA déductible, TVA à décaisser/crédit) and generates the French/OHADA-style TVA return form with line references. A scenario toggle switches between monthly and quarterly filing periods.

**Minimum viable inputs / outputs:**
- Inputs: transaction rows (date, nature, HT amount, TVA rate %)
- Outputs: TVA register table, net TVA payable/refundable, journal entries (Account 4456 / 4457 / 445711)

**Complements existing playgrounds:** Journal Entry teaches the mechanics; this playground adds the tax-reporting context and the account-code discipline (SYSCOHADA class 4 accounts).

### Idea B — Payroll & Social Contributions Calculator
**Title (EN):** Payroll & Social Charges  
**Title (FR):** Bulletin de paie & Charges sociales  
**Target learner:** Licence 3, Master 1, practicing HR/accounting professional  
**Pedagogical objective:** OHADA-zone payroll involves CNPS contributions, income tax (IRPP), and transport/housing allowances that vary by country. Most students can't reconcile gross-to-net without a structured model.

**Core interaction:** Learner enters gross salary, country (Cameroon / Côte d'Ivoire / Sénégal), statutory allowances, and pension grade. The playground computes payslip line-by-line (cotisations salariales, cotisations patronales, base taxable, IRPP, net à payer) and produces the required journal entries in SYSCOHADA accounts (641, 645, 431, 447).

**Minimum viable inputs / outputs:**
- Inputs: gross salary, country, category (cadre/employé/ouvrier), months YTD
- Outputs: detailed payslip, journal entries, total employer cost

**Complements existing playgrounds:** This is the only HR-accounting intersection; CVP shows labor as a fixed cost without showing how it's calculated.

### Idea C — Inventory Valuation (FIFO / CUMP / LIFO)
**Title (EN):** Inventory Costing Methods  
**Title (FR):** Valorisation des stocks  
**Target learner:** Licence 1–2  
**Pedagogical objective:** Learners struggle to understand how the choice of FIFO, CUMP (weighted-average), or LIFO changes COGS and ending inventory. The numerical difference only becomes concrete through interactivity.

**Core interaction:** Learner enters a sequence of inventory movements (purchases and sales with quantities and unit costs). The playground recalculates the entire stock card in real time under the selected method, highlights which units are consumed, and shows the P&L impact side-by-side for FIFO vs CUMP. LIFO shown as a comparison only (not permitted under SYSCOHADA but useful for IFRS/US-GAAP contrast).

**Minimum viable inputs / outputs:**
- Inputs: movement table (date, type buy/sell, qty, unit cost)
- Outputs: stock card (fiche de stock), COGS, ending inventory value, comparison table

**Complements existing playgrounds:** Depreciation handles asset life-cycle; this handles current-asset valuation — SYSCOHADA class 3 accounts.

### Idea D — Financial Ratio Dashboard
**Title (EN):** Financial Ratio Analyzer  
**Title (FR):** Analyse par ratios financiers  
**Target learner:** Licence 3, Master  
**Pedagogical objective:** Students memorize ratio formulas but can't interpret them in context. An interactive balance sheet and income statement where sliders change line items — and all ratios update live — builds intuition for sensitivity.

**Core interaction:** Learner inputs or adjusts a simplified balance sheet (Actif / Passif) and income statement following SYSCOHADA Tableau de Synthèse layout. The playground computes ~15 key ratios (solvabilité, liquidité générale/réduite/immédiate, rentabilité économique/financière, capacité d'autofinancement) with color-coded bands (healthy / caution / danger). A "What-if" mode lets learners move a single line item and see how all ratios shift.

**Minimum viable inputs / outputs:**
- Inputs: simplified BS and IS line items (pre-populated with a default OHADA firm)
- Outputs: ratio table with interpretation bands, radar chart, sensitivity strip

**Complements existing playgrounds:** CVP focuses on managerial profit levers; this focuses on the external financial health picture from auditor and creditor perspectives.

### Idea E — Provisions & Contingent Liabilities
**Title (EN):** Provisions & Depreciation of Receivables  
**Title (FR):** Provisions & Dépréciation des créances  
**Target learner:** Licence 3, Master 1  
**Pedagogical objective:** Learners confuse provisions (uncertain future obligations) with depreciation (asset value write-down) and with accruals. SYSCOHADA has specific account trees for each; this playground enforces the distinction through scenario-based journal entry validation.

**Core interaction:** Learner is presented with a scenario (doubtful receivable, pending lawsuit, warranty obligation). They must (1) decide whether a provision is required under SYSCOHADA criteria, (2) estimate the amount, and (3) record the journal entry. The playground grades the entry and gives structured feedback on account choice (accounts 39x, 49x, 59x for depreciation; 19x for provisions) and balance-sheet classification.

**Minimum viable inputs / outputs:**
- Inputs: scenario selection, provision amount, journal entry (debit/credit rows)
- Outputs: graded answer with account-level feedback, balance-sheet impact preview

**Complements existing playgrounds:** Journal Entry playground teaches the mechanics; this applies them to the specific sub-domain that students find most conceptually confusing in SYSCOHADA exams.
