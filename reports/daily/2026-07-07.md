## 1. Bugs & Issues

### [HIGH] Server boundary violation — client component imports from `$lib/server/`

**File:** `src/lib/components/feedback/FeedbackForm.svelte:7`  
```ts
import type { FeedbackType, FeedbackSeverity } from '$lib/server/db/types';
```
A client-side Svelte component references `$lib/server/`. Although `import type` is erased at runtime today, SvelteKit's boundary enforcement exists precisely to catch this pattern, and any future change to a value import would silently leak DB types to the client bundle. The component only needs `FeedbackType` and `FeedbackSeverity` for its form state — these are simple string unions that belong in a shared (non-server) types file.

**Fix:** Move `FeedbackType`, `FeedbackSeverity` (and any other purely structural types) out of `$lib/server/db/types.ts` into a new `$lib/types/feedback.ts`, then import from there in both the server and the client.

### [MEDIUM] Hardcoded hex color map in JS — `CategoryBreakdownDonut`

**File:** `src/lib/playgrounds/bank-reconciliation/components/CategoryBreakdownDonut.svelte:30-40`
```ts
const CATEGORY_COLORS: Record<ItemCategory, string> = {
  'outstanding-check': '#6ea8fe',
  'deposit-in-transit': '#22c55e',
  // … 7 more hex literals
};
```
These hex values are written directly into SVG `stroke` attributes, bypassing the theme token system. A theme change in `tokens.ts` will not affect these colors.

**Fix:** Read the values from computed CSS custom properties at mount time:
```ts
function cssVar(name: string): string {
  return getComputedStyle(document.documentElement).getPropertyValue(name).trim();
}
const CATEGORY_COLORS: Record<ItemCategory, string> = {
  'outstanding-check': cssVar('--accent'),
  'deposit-in-transit': cssVar('--green'),
  // …
};
```
Or define a data-visualization palette in `tokens.ts` and export it for consumption by charting code.

### Idea 1 — VAT / TVA Declaration Simulator

**EN:** VAT Declaration Simulator  
**FR:** Simulateur de déclaration de TVA  
**Target learner:** Licence 2 / practicing professional  
**Pedagogical objective:** Students confuse TVA collectée (output tax) vs TVA déductible (input tax) and miscalculate net payable. This playground makes the cash-flow direction of each transaction viscerally clear.  
**Core interaction:** The learner records a set of sales and purchases in a month. For each line they classify whether VAT is collected or deductible. The running "TVA à décaisser / à récupérer" balance updates live. A submission panel generates the monthly statement in the SYSCOHADA journal format (account 4457 / 4456).  
**Inputs:** 3–10 sales lines (amount HT, TVA rate 18 % / 8 % / 0 % per OHADA schedule), 3–8 purchase lines (amount HT, deductibility: full / partial / excluded), carry-forward credit from prior month.  
**Outputs:** TVA collectée total, TVA déductible total, net payable or credit, journal entries (debit/credit), printable declaration stub.  
**Why it complements existing playgrounds:** Extends the Journal Entry playground into a tax-specific workflow; no VAT theme exists today. Directly implements the multi-rate TVA table required by SYSCOHADA Révisé 2017.

### Idea 2 — Fixed-Asset Register & SYSCOHADA Depreciation Tracker

**EN:** Fixed-Asset Register  
**FR:** Registre des immobilisations  
**Target learner:** Licence 3 / Master  
**Pedagogical objective:** Students treat depreciation as a single calculation, not as a ledger movement across fiscal years. They miss how the carrying value, accumulated depreciation, and net book value evolve together — and how the SYSCOHADA register format differs from IFRS.  
**Core interaction:** The learner adds 1–5 assets (cost, date, useful life, depreciation method). A live register table shows each asset row: gross value, accumulated depreciation per year, net book value, and the year-end journal entry (debit 681X / credit 28XX per the OHADA chart of accounts). Clicking any year shows the prorated calculation for partial-year acquisitions.  
**Inputs:** Asset cost (multi-currency via shared formatter), acquisition date, useful life (years), residual value, depreciation method (linear / degressive / UOP).  
**Outputs:** Year-by-year register table, cumulative chart (gross / net book value), SYSCOHADA journal entries per fiscal year, total depreciation charged to income.  
**Why it complements existing playgrounds:** The existing Depreciation playground is a legacy iframe with a single-asset, single-method focus. This native module would add multi-asset tracking and SYSCOHADA-specific account coding, which the legacy file cannot do without a full rewrite. Implements `PlaygroundModule` and shares the existing `fmtCurrency` / `renderMarkdown` / i18n systems.

### Idea 3 — Payroll & Social Charges Calculator (OHADA Labour Law)

**EN:** Payroll & Social Charges Calculator  
**FR:** Calculateur de paie et charges sociales  
**Target learner:** Licence 3 / Master / practicing professional  
**Pedagogical objective:** Payroll is one of the most complex recurring journal entries. Students incorrectly map gross wage, net wage, employee contributions, and employer contributions to SYSCOHADA accounts (641, 421, 431, 437, 447). The relationship between the salary slip and the journal entry is unclear.  
**Core interaction:** The learner enters a gross salary. The tool applies CNPS / CRTV / IRPP rules (configurable per OHADA-zone country) and shows a real-time salary slip broken into gross, employee deductions, net payable, and employer charges. Each figure is linked to its SYSCOHADA account code. A journal-entry preview shows the full payroll booking.  
**Inputs:** Gross monthly salary, country selector (Cameroon / Côte d'Ivoire / Sénégal / generic OHADA), employment category (permanent / contractor), number of dependants (for IRPP), employer contribution rate override.  
**Outputs:** Salary slip summary, employer cost total, employee net pay, SYSCOHADA journal entry with account codes, social charges breakdown chart.  
**Why it complements existing playgrounds:** No HR/payroll module exists. SYSCOHADA accounts 64X are covered nowhere in the current set. The country-selector approach reuses the existing currency/locale preferences infrastructure.

### Idea 4 — Working Capital & Cash Conversion Cycle Analyser

**EN:** Working Capital Analyser  
**FR:** Analyseur du besoin en fonds de roulement  
**Target learner:** Licence 3 / Master  
**Pedagogical objective:** Students know the BFR formula but cannot trace it back to balance-sheet movements or understand how the cash conversion cycle (CCC) changes with industry. They also confuse BFR (besoin en fonds de roulement) with FR (fonds de roulement) and TN (trésorerie nette).  
**Core interaction:** The learner inputs three balance-sheet blocks (stocks, créances clients, dettes fournisseurs) and an annual revenue figure. The playground derives BFR, FR, TN, DSO, DPO, DIO, and CCC in real time. A timeline chart shows how changing the collection period or payment terms shifts the cash gap.  
**Inputs:** Stock value, days of inventory on hand, accounts receivable, days sales outstanding, accounts payable, days payable outstanding, annual revenue, cost of sales.  
**Outputs:** BFR = stocks + créances − dettes, FR = capitaux permanents − actif immobilisé, TN = FR − BFR, CCC = DIO + DSO − DPO, cash gap chart, sensitivity table (what happens if DPO improves 10 days).  
**Why it complements existing playgrounds:** Sits between the TVM playground (time value) and bank reconciliation (cash flow) with a balance-sheet literacy focus specific to SYSCOHADA. No working-capital module exists today.

### Idea 5 — Ratio Analysis Workbench (SYSCOHADA Balance Sheet)

**EN:** Financial Ratio Workbench  
**FR:** Atelier d'analyse financière  
**Target learner:** Licence 3 / Master  
**Pedagogical objective:** Students can compute individual ratios but fail to read a ratio set holistically or understand which ratios change together. They also struggle mapping SYSCOHADA account classes to standard ratio numerators/denominators (e.g., SYSCOHADA class 1 ≠ IFRS long-term liabilities exactly).  
**Core interaction:** The learner fills in a simplified SYSCOHADA balance sheet and income statement (≤ 15 cells). The playground auto-computes a dashboard of 12 ratios (solvency, liquidity, profitability, activity) and explains the SYSCOHADA account mapping for each. An industry benchmark slider lets the learner compare their numbers against stylised sector norms (commerce / industry / services in the OHADA zone). A "what-if" panel lets them tweak one line and see which ratios move and why.  
**Inputs:** Total actif / passif (classes 1–5 SYSCOHADA), chiffre d'affaires, résultat net, amortissements.  
**Outputs:** 12-ratio dashboard with traffic-light indicators, waterfall showing how equity changes affect the solvency ratios, sector comparison bar chart, plain-language interpretation in EN/FR.  
**Why it complements existing playgrounds:** No ratio-analysis module exists. Complements the CVP playground (profitability) and TVM playground (investment returns) by adding a balance-sheet lens. The 12-ratio set aligns with the SYSCOHADA Révisé 2017 financial-analysis framework taught in Licence 3 / DESCF programmes.
