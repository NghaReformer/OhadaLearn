### BUG-01 · HIGH · Missing `--orange` CSS token — hardcoded fallback hex active in production

**Files**
- `src/lib/components/playground/KpiStrip.svelte:76`
- `src/lib/playgrounds/amortization/components/ScheduleTable.svelte:240`
- `src/lib/playgrounds/amortization/components/ChartPanel.svelte:436`
- `src/lib/playgrounds/amortization/components/ChartPanel.svelte:493`

**Explanation**
`--orange` is referenced with a hardcoded fallback (`var(--orange, #f59e0b)`) in four places, but `--orange` is never declared in `src/lib/theme/tokens.ts` or `src/lib/theme/css-generator.ts`. Because the property is undefined, browsers silently resolve to the fallback `#f59e0b` — a Tailwind amber-400 value that differs from the theme's own `--amber` (`#f5a623`). The design system's "change one file to restyle everything" guarantee is broken for these tokens.

**Suggested fix**
Add an `orange` color to `ThemeTokens.colors`, set a value in `defaultTheme` (or alias it to an existing amber shade), and emit `--orange: ${c.orange};` in `css-generator.ts`. Remove all fallback hex literals from the four call sites.

### BUG-02 · HIGH · Hardcoded hex palette in `CategoryBreakdownDonut.svelte`

**File** `src/lib/playgrounds/bank-reconciliation/components/CategoryBreakdownDonut.svelte:30-39, 120`

**Explanation**
`CATEGORY_COLORS` maps nine reconciliation categories to hard-coded hex values (`#6ea8fe`, `#22c55e`, `#f59e0b`, `#10b981`, `#ef4444`, `#a855f7`, `#06b6d4`, `#ec4899`, `#fb923c`). A theme change has no effect on the donut chart or its legend, and the colours are already out-of-step with the token palette (e.g., `#ef4444` vs theme `--error: #f06070`).

**Suggested fix**

Drive both the SVG `stroke` attribute and the legend swatch from these strings; the inline `style` on the legend can then remain (`style="background: {seg.color}"`) because the value is now a `var(…)` reference rather than a hex literal.

### BUG-04 · MEDIUM · Inline `style=` attributes in bank-reconciliation components

**Files**
- `src/lib/playgrounds/bank-reconciliation/components/CategoryBreakdownDonut.svelte:120`
- `src/lib/playgrounds/bank-reconciliation/components/MatchingPairsOverlay.svelte:88, 108`

- `src/lib/playgrounds/bank-reconciliation/components/ScenarioWalkthrough.svelte:62`
- `src/lib/playgrounds/bank-reconciliation/components/ReconciliationFlow.svelte:122, 133, 160`

**Explanation**
CLAUDE.md bans inline styles. The instances above use `style=` for dynamic values: container dimensions (`width/height`), animated bar heights, progress fill widths, SVG transforms, and animation delays. While some are genuinely dynamic, others (e.g., `opacity: 0.4 + $meetTween * 0.6`) could use CSS custom properties set via Svelte's `style:` directive or `--custom-prop={value}` instead.

**Suggested fix**
For single-property bindings, prefer Svelte's `style:property={value}` directive over a `style=` string (already done correctly in `ExercisePanel:42` with `style:background`). For SVG transforms that require multi-property strings, the inline is acceptable as a last resort — document it with a brief comment.

### PG-01 · Working Capital Cycle Simulator
**FR:** Simulateur du Cycle Fonds de Roulement

**Target learner:** Licence 3 / Master 1

**Pedagogical objective**
Students routinely confuse Fonds de Roulement (FR), Besoin en Fonds de Roulement (BFR), and Trésorerie Nette (TN). The identity `TN = FR − BFR` feels abstract until they manipulate real balance sheet levers.

**Core interaction**
A simplified SYSCOHADA balance sheet split into permanent capital (equity + long-term debt) and long-term assets on one side, and current assets vs current liabilities on the other. Sliders adjust stock days, debtor days, and creditor days. FR, BFR, and TN update in real time with a waterfall diagram showing the liquidity cushion or shortfall.

**Minimum viable inputs / outputs**
- Inputs: fixed assets, equity, long-term debt, revenue, gross margin %, stock turnover days, debtor days, creditor days
- Outputs: FR, BFR, TN, color-coded balance verdict (healthy / squeezed / negative TN alert)

**Why it complements existing playgrounds**
Amortization and Journal Entry cover the recording cycle; this playground covers the financial analysis phase that follows — closing the accounting-to-decision-making loop.

### PG-02 · Financial Ratios Dashboard
**FR:** Tableau de Bord des Ratios Financiers SYSCOHADA

**Target learner:** Licence 2 / Licence 3

**Pedagogical objective**
Students can compute individual ratios but struggle to read a ratio set holistically and identify which lever to pull. This playground builds pattern recognition across the four standard SYSCOHADA ratio families.

**Core interaction**
Two simplified SYSCOHADA-format statements (bilan + compte de résultat). Students enter or adjust line items; the dashboard computes and visualises 12 ratios across four categories: liquidity (FR/BFR/current ratio), profitability (ROE, ROA, net margin), leverage (gearing, debt-service cover), and activity (asset turnover, receivables days). A "scenario" preset system lets instructors pre-load typical firm profiles (manufacturing SME, service firm, distressed company).

**Minimum viable inputs / outputs**
- Inputs: ~15 balance sheet lines + ~8 P&L lines
- Outputs: 12 computed ratios, each with a benchmark range indicator and a one-line SYSCOHADA-grounded interpretation (via i18n strings)

**Why it complements existing playgrounds**
CVP focuses on cost-volume-profit in isolation. This playground aggregates across the full financial picture and teaches cross-ratio reasoning — a Master-level skill not covered elsewhere.

### PG-03 · VAT / TVA Reconciliation Trainer
**FR:** Simulateur de Déclaration TVA

**Target learner:** Licence 2 / practicing professional

**Pedagogical objective**
TVA accounting is the most frequent source of errors in OHADA-zone SME bookkeeping. Learners confuse collectée vs déductible vs à décaisser, forget the prorata rule for mixed-use businesses, and mis-classify exempt vs taxable operations.

**Core interaction**
A month's worth of synthetic purchase and sales invoices (5–10 lines each). Students classify each invoice as taxable/exempt, tick the eligible deductions, apply the TVA rate (18 % CEMAC / UEMOA standard), and compute TVA collectée, TVA déductible, and net TVA payable. A split-pane view shows the resulting journal entries in real time. Wrong classifications produce an immediate diff against the model answer.

**Minimum viable inputs / outputs**
- Inputs: invoice list with amount + TVA rate; student-selected category per row
- Outputs: TVA collectée, TVA déductible, net payable / receivable; journal entry preview; error diff

**Why it complements existing playgrounds**
Bank Reconciliation covers the cash-book gap; this playground covers the tax-liability gap — both are reconciliation exercises but target different SYSCOHADA accounts (445x vs 512x).

### PG-04 · Depreciation Method Comparator
**FR:** Comparateur de Méthodes d'Amortissement SYSCOHADA

**Target learner:** Licence 2

**Pedagogical objective**
The legacy static playground covers one depreciation scenario at a time. Students do not develop an intuition for why straight-line, declining-balance, and units-of-production methods diverge, nor when SYSCOHADA mandates component depreciation.

**Core interaction**
A single asset entry (cost, residual value, useful life, annual usage). Three side-by-side tables show the full depreciation schedule for each method. An overlay chart superimposes book value curves. A "component" toggle splits the asset into two components with different lives and shows the blended schedule.

**Minimum viable inputs / outputs**
- Inputs: cost, residual, life (years), annual units produced / capacity, component split (%)
- Outputs: 3 × schedule tables, book value chart, total depreciation per period, SYSCOHADA account codes (281x / 68x) auto-populated

**Why it complements existing playgrounds**
The legacy `depreciation-playground.html` is an iframe static page with no native integration. This proposal replaces it with a native Svelte module implementing `PlaygroundModule` from `src/lib/contracts/playground.ts`, unlocking exercises, i18n, and theme integration that the static file cannot provide.

### PG-05 · Payroll & Social Charge Calculator
**FR:** Simulateur de Paie et Charges Sociales

**Target learner:** Licence 3 / Master / practicing professional

**Pedagogical objective**
Payroll accounting in OHADA-zone countries involves CNPS/CNSS contributions, IRPP withholding at progressive brackets, and employer charges that vary by country. Students struggle to reconcile the gross-to-net waterfall and the corresponding debit/credit entries.

**Core interaction**
A single employee record (country selector: Cameroon / Senegal / Côte d'Ivoire / default OHADA). Students enter gross salary; the calculator walks through each deduction tier with an expanding step-by-step breakdown (IRPP bracket highlight, CNPS employee + employer shares). A live journal entry shows the salary expense, social charge payable, withholding payable, and net wages payable split across SYSCOHADA accounts (661x, 431x, 447x, 422x).

**Minimum viable inputs / outputs**
- Inputs: gross salary, country/fiscal regime, number of dependants (for IRPP deduction)
- Outputs: step-by-step gross-to-net waterfall, employer cost total, journal entry skeleton, downloadable payslip summary

**Why it complements existing playgrounds**
No existing playground touches labour cost accounting. Payroll is the second most common journal entry type in any operating company, making this a high-value addition for Licence 3 and professional learners.
